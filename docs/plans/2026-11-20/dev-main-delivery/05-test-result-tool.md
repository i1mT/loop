# 阶段 05 · 用工具提交环境测试结论

## 阶段目标

预览测试和生产回归共用结构化的结果入口。智能体在原 ACP 会话完成验证后提交结论，Loop 按结果推进。

## 范围

七节点交付流程中的环境测试。旧四节点流程的发布结论和技术方案继续按各自已有的接口处理。

## Todo

- [ ] ACP 恢复原会话时注入 `report_environment_test`。未展示 MCP 工具的适配器可通过同一程序的命令行入口提交。
- [ ] 每次测试独立接收 `passed`、`failed` 或 `blocked` 和摘要。重报相同结果可成功，冲突结果拒绝覆盖。通过现有租约、轮次和部署提交校验推进交付。
- [ ] 验证旧“没有返回明确的测试通过结果”错误可以进入重试。由新版 daemon 在原会话重新测试并调用工具。

## 测试方案

使用一次性 Git 仓库和测试智能体验证通过、失败后修复、只有文字时仍停在测试节点和命令行兼容路径。使用 Grok 验证真实 MCP 调用和原会话恢复。

## 完成门禁

预览通过进入生产确认，失败进入修复，受阻保留原因。生产回归通过进入已发布。仅输出聊天文本不会触发阶段推进。Grok 在原会话里实际调用工具。
