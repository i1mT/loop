# dev 预览与 main 生产交付改造

本计划把 Loop 的现有任务流程扩展为七个节点，统一使用 `dev` 部署预览、`main` 部署生产。

- 目标、决策、进度和验证记录见 [progress.md](progress.md)。
- 阶段 01 建立状态、项目设置和迁移边界。[状态与项目设置](01-state-and-settings.md)
- 阶段 02 完成自动合并 dev、查询预览流水线和智能体验证。[预览部署与测试](02-preview.md)
- 阶段 03 完成共享生产 PR/MR、人工合并、生产部署与回归。[生产发布与回归](03-production.md)
- 阶段 04 处理流水线和生产回归失败。[失败恢复与生产确认](04-recovery-and-review.md)
- 阶段 05 给环境测试注入结构化结果工具。[用工具提交环境测试结论](05-test-result-tool.md)

## 执行约定

1. 先读本文件和 `progress.md`，然后读取当前或下一阶段。上一阶段达到完成条件后再进入下一阶段。
2. 每完成一个可验证的改动，在 `progress.md` 记录命令、结果和剩余事项。交接或中断前写清下一条可执行动作和阻断。
3. 阶段文档保存目标和验收方式。实际状态和实施偏差统一写入 `progress.md`。发现设计需要调整时，先记录原因和影响，再更新相关阶段。
4. 每阶段对照通过条件复核状态、迁移、失败恢复和测试证据。遵循[仓库开发约定](../../../../AGENTS.md)，使用一次性仓库和合成测试账号。
5. 保留原机器、worktree、会话、轮次和租约边界。人工合入生产时以点击时确认的源分支提交为准。
