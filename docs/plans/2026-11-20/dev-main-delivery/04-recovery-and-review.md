# 阶段 04 · 失败恢复与生产确认

## 阶段目标

让流水线和生产回归失败后继续推进，同时让生产确认准确展示本次会发什么。

## Todo

- [ ] GitHub 和 GitLab 返回失败任务和日志，临时故障自动重跑。记录已尝试的失败，重复失败交给用户处理。
- [ ] 流水线代码问题与生产回归失败交给原会话修复。保留生产失败记录，修复重新走 dev 预览和生产确认。
- [ ] 按待合并的 dev 提交列出任务及验证状态，保留已有的人工合并检查。

## 测试方案

用模拟托管接口和一次性 Git 仓库验证日志、重跑和同一错误连续出现。用独立数据库验证生产失败后的新轮次及历史，检查 900px 和 1440px 的生产确认界面。

## 完成门禁

临时失败能继续，确定的代码失败会回到原会话。生产回归失败记录可追溯，原会话修复后仍需确认新的生产提交。确认窗口会列出批次内已通过、待验证和修复中的任务。

## 交付物

流水线恢复、生产回归修复、批次确认界面和相应测试。
